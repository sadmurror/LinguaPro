# Ревью материалов проекта

## Чек-лист

1.	У каждого пользователя есть хотя бы одна функция в требованиях?
2.	Для каждого требования есть модуль в архитектуре?
3.	Есть ли несоответствие между связями классов в диаграмме и таблице классов?
4.	На каждое требование есть хотя бы один тест-кейс?
5.	Все ли шаги сценариев соответствуют функциональным требованиям?

## Таблица замечаний

| № | Где | Замечание | Как исправить |
|---|-----|-----------|---------------|
| 1 | Требования (requirements.docx) | Для бухгалтера не было указано ни одной функции в функциональных требованиях, хотя в таблице его роль описана, но она закреплена за другими должностями и системой. | Добавить требование о просмотре начислений, проверке финансовой отчетности. |
| 2 | Архитектура (architecture.docx) | Ни один из модулей не отвечает за резервное копирование и аудит действий, которые прописаны в требовании 28 и 31. Модуль авторизации и ролей покрывает доступ и сессии, но не эти функции. | Расширить модуль авторизации и ролей, включив в него резервное копирование и журнал аудита. |
| 3 | Диаграмма классов (test-cases.docx) | В строке класса User присутствует связь с классами Profile и Role, которых не существует в данной таблице классов и на диаграмме, а их функционал покрывают другие классы. | Убрать связь между классом User и несуществующими классами Profile и Role. |
| 4 | Тест-кейсы (test-cases.docx) | Нет тест-кейса на просмотр гостем открытой информации о курсах без регистрации. | Добавить тест-кейс. |
